CONTEXT

业务问题

发票工作簿包含有用的出货信息，但跨文件分析需要一致的数据粒度、类型与可追溯的转换。

APPROACH

范围与方法

文档中的设计使用 DuckDB、Python 和 SQL，划分 raw、staging 与 mart 层，以发票行项目为事实粒度，并提供出货、目的地和数据质量分析视图。

OUTPUT

项目包含什么

  • 单文件本地 DuckDB 数据库
  • 类型明确、去重后的发票行数据
  • SQL 视图与 Notebook 分析

EVALUATION

下一步如何评估

重复率、必填字段完整性及源数据与报告的一致性。

以上是后续验证时建议采用的评估指标，不代表已测得的改进成果。

证据与边界

架构来源于源仓库文档；本次未独立验证导入幂等性与分析结果，也未分发任何发票记录。
